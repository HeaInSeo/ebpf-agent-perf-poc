# 실험 기록 및 검토 원칙 (Experiment Record Policy)

모든 PoC 실험은 **코드+실행+증거+판정**을 재현 가능한 단위로 보존한다.
작업 완료 선언만으로 실험 PASS를 부여하지 않는다.

1. 실험 시작 전에 목적, 단일 가설, 성공·실패·중단 기준을 문서화한다.
2. 비교 대상, 고정 Git SHA, 도구 버전, OS·커널·하드웨어·권한·환경 제약을 기록한다.
3. 실행 명령, 입력·부하·시드, 반복 횟수, 계측 조건, 메트릭과 계산법을 기록한다.
4. GitHub Actions run URL, job 결과, 원시 로그·JSON·아티팩트 ID/해시를 연결한다.
5. 결과 해석은 관찰 사실과 원인 가설을 구분하고, 계측 오버헤드와 오차를 표시한다.
6. FAIL → 수정 → 재실행 이력을 지우지 않는다. 각 시도에 별도 SHA와 run URL을 둔다.
7. 성능 주장은 기능 동등성 확인과 환경 통제 후에만 하고, 증거 부족 시 INCONCLUSIVE로 판정한다.
8. GitHub 아티팩트 보존 기한을 넘겨도 검토 가능하도록 보안 검토한 최소 원시 증거를 보존한다.
9. 외부 공개 저장소에 자격증명, 토큰, 개인·서버 비공개 정보, 민감 원문을 커밋하지 않는다.
10. 마지막으로 별도 검토자가 재실행·반증할 수 있는 절차와 다음 실험을 명시한다.

실험 보고서는 [템플릿](experiments/TEMPLATE.md)을 사용한다.
